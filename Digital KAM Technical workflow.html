02 · Key flows

Three paths the demo should show

AC 5 · Import

Excel workbook to living plan

  1. User uploads a KAM .xlsx. The API stores it in Blob Storage.
  2. A blob-trigger Function parses it with openpyxl.
  3. Gemini maps non-standard cells to the KAM schema and gives a confidence score per field.
  4. A deterministic validator checks required fields, RACI, A/B/C importance and dates.
  5. The validation report is shown in the UI. The user confirms and the plan lands in Azure SQL as version 1.
AC 8 · AI

Next best action

  1. A nightly Function, or the “Suggest” button, calls the orchestrator.
  2. Claude calls tools: plan gaps, scores, stakeholder map, overdue actions.
  3. It returns JSON: what to do, whose help, which channel, why, at-risk flag, source sections.
  4. The output is schema-checked and logged with model, prompt and tokens.
  5. The user accepts it and it becomes a tracked action linked to its section.
AC 2 · 3 · 4 · Cadence

Continuous planning loop

  1. Every save creates a new version through SQL temporal tables.
  2. The scoring engine recalculates opportunity, brickwall, checklist and perception scores.
  3. Timer Functions flag stale sections and overdue actions, then raise in-app reminders.
  4. A nightly extract moves data to Databricks, where score trends are built for the MAC and Power BI views.

04 · AI agents

Six agents, each with one job

Each agent returns structured JSON checked against a schema. A person accepts every AI suggestion before it changes a plan.

Claude Sonnet 5 · tool use

Next Best Action

Recommends what to do next for each account, whose help to seek, which channel to use and why. It works from plan gaps, scores, the stakeholder map and overdue actions.

out → action, helper, channel, rationale, at_risk, source_sections
Gemini · long context

Workbook Interpreter

Maps legacy Excel layouts to the KAM schema, gives a confidence score per field and explains what it could not map.

out → mapped rows + validation findings
Groq · Llama

Plan Copilot

Helps users while they fill in sections. It drafts vision and objectives, suggests strategies and checklist answers, and summarises stakeholder notes.

out → draft text the user edits or rejects
Claude Haiku 4.5 · nightly batch

Risk Sentinel

Reads score trends, stale sections and overdue actions from Databricks gold tables, then flags at-risk accounts with a plain-language reason.

out → risk level, drivers, flagged sections
Claude Sonnet 5

Executive Briefer

Writes the portfolio narrative for the Executive export pack and the MAC view: what moved, where it is at risk and where to invest.

out → briefing sections with cited accounts
Ollama · local model

Synthetic Data & Evaluator

Creates realistic fictional accounts for the demo and tests. Scores the other agents' outputs against a rubric in the test suite.

out → seed data, eval scores per agent
  • Synthetic or public data only. No customer data or Psiog IP goes to any model.
  • Keys stay in Key Vault and are only called server-side through the orchestrator.
  • Every AI call is logged with agent, model, tokens and outcome in an AI audit table.
  • A token budget per agent, response caching and a provider fallback keep us running if one model hits its rate limit.
